0.1 ~25 min

🤖 What a coding agent is (and why it isn’t a chatbot)

The difference that changes everything: one responds, the other works. Here, you’ll learn what Claude Code really is.

What it is:

A chatbot returns text. You ask, it answers—and that’s it. It doesn’t open any files or run any commands.

Why learn:

Without understanding this limit, you expect a chatbot to do something only an agent can do—and end up frustrated without knowing why.

Key concepts:

Text input → text output. No real action on your computer.

What it is:

A coding agent reads files, writes files, runs commands in the terminal, and returns a result that has already happened—not just a description of what “could” happen.

Why learn:

It's this ability to act that turns “conversation” into “real automation”—the foundation of everything else in the course.

Key concepts:

Tools, real execution, verifiable result.

What it is:

Think of Claude Code as a new employee: you give it the task, it decides how to do it, carries it out, and comes back to show you the result.

Why learn:

This analogy guides how to ask, how to supervise, and when to trust more or less — a central topic in Track 0.6.

Key concepts:

Delegation, supervision, growing trust.

What it is:

A program that runs in your terminal, connected to an Anthropic AI model, with permission (which you grant) to read and write files and run commands.

Why learn:

Knowing “what it is” removes the mystery and makes you comfortable installing and using it without fear — the topic of module 0.2.

Key concepts:

Terminal program, AI model, permission granted by you.

What it is:

Each message exchanged consumes "tokens" — the AI billing unit — and a typical simple automation session costs a few cents to a few reais.

Why learn:

Without this understanding, cost becomes an abstract fear that gets in the way of learning—it’s better to face the real number.

Key concepts:

Token, cost per session, estimate (not a fixed bill).

What it is:

Install → understand the project folder → write the CLAUDE.md → learn plan mode → set the security rules.

Why learn:

Seeing the complete path helps you stay on track — each module builds on the previous one.

Key concepts:

Progression: install, organize, guide, review, protect.

⌨️ Installation on Windows/Mac/Linux, no fear of the terminal

The terminal doesn’t bite. Step-by-step installation on all three systems and the four commands you need to know.

What it is:

A simple text window where you type commands and the computer runs them right away — without clicking any icons.

Why learn:

This is where Claude Code runs. Getting over your fear of the terminal is the first step in the whole course.

Key concepts:

Prompt (the “blinking cursor” waiting for a command), type + Enter.

What it is:

The recommended path on Windows is to enable WSL (Linux inside Windows) and install it there.

Why learn:

Avoids 90% of the compatibility problems that come up when trying to install directly on plain Windows.

Key concepts:

WSL, Windows Terminal, restart after enabling.

What it is:

Open the Terminal app (it’s already installed) and paste a single installation command.

Why learn:

This is the most direct path—without an extra layer like WSL.

Key concepts:

Native terminal, official installation script.

What it is:

cd changes folders; ls (Mac/Linux) or dir (Windows) lists what's inside it.

Why learn:

These are the only two commands you use all the time before calling the agent.

Key concepts:

Current folder, navigation, listing.

What it is:

Run a version command and see a number appear — a sign that the installation succeeded.

Why learn:

Avoids moving forward with a broken installation.

Key concepts:

Verification command, version number.

What it is:

Type the command that opens Claude Code inside a folder and send the first message.

Why learn:

This is the course’s “hello world”—from here on, it’s all practice.

Key concepts:

Session, input prompt, agent response.

📁 Anatomy of a project

What a project folder is, what a repository is, and what Claude Code creates behind the scenes.

What it is:

A regular folder on your computer, dedicated to a project — nothing magical, just organization.

Why learn:

The agent only sees what’s inside the open folder—mixing projects confuses the context.

Key concepts:

One project = one folder = one context.

What it is:

A project folder with a saved version history (via git) — every change is recorded and can be undone.

Why learn:

This is what will let you “publish” the automation in Learning Path 4.

Key concepts:

Repository (repo), version history, git.

What it is:

Common folders: source code, configuration files, the CLAUDE.md, and a `.claude/` folder with skills and preferences.

Why learn:

Recognizing these names prevents confusion when the agent mentions one of them.

Key concepts:

Source code, configuration, `.claude/`.

What it is:

The files stay on your computer; only the conversation text and necessary excerpts travel to the AI model to generate the response.

Why learn:

Addresses the question “are my files exposed?” — revisited in module 0.6.

Key concepts:

Local vs. cloud, what flows in each message.

What it is:

Create a new folder, navigate into it in the terminal, and open Claude Code inside it.

Why learn:

This is the ritual you’ll repeat for every new automation in the course.

Key concepts:

mkdir, cd, open the agent in the right folder.

What it is:

Mixing several projects in a single folder, or opening the agent in the wrong folder (e.g., the user’s home directory).

Why learn:

Prevents the agent from accidentally “seeing” and changing files from other projects.

Key concepts:

One project per folder; always open it in the right place.

🧠 CLAUDE.md as the project’s brain

The file the agent reads every session. Why lean beats huge—and a real example to copy.

What it is:

A plain text file at the project root that the agent reads automatically whenever it opens the folder.

Why learn:

This is how you “teach” fixed rules to the agent without repeating them in every conversation.

Key concepts:

Automatic loading, persistent rules.

What it is:

Each new conversation session "forgets" the previous conversation. CLAUDE.md is how you give the agent a minimal sense of continuity.

Why learn:

Explains why you should put key information there, instead of just saying it out loud.

Key concepts:

New session, cleared memory, persistent context via file.

What it is:

A well-written 20-line CLAUDE.md gives better guidance than a generic 500-line one—the agent reads everything, and too much information dilutes what matters.

Why learn:

This is the most common mistake beginners make: “documenting everything” in the wrong file.

Key concepts:

Signal vs. noise, essential rules first.

What it is:

A ready-to-use template for a concise CLAUDE.md that you can adapt to your project (complete in module 0.4).

Why learn:

Copying a good example is faster than learning the structure from scratch.

Key concepts:

Sections: goal, rules, commands, what never to do.

What it is:

If the project grows, put extra details in separate files referenced by CLAUDE.md—not inside it.

Why learn:

Sets the stage for the concept of skills, explored in depth in Track 3.

Key concepts:

Point instead of bloating.

What it is:

Ask to "summarize this project" right after writing the file — if the response matches what you wrote, it worked.

Why learn:

This is the final exercise in the learning path, completed in module 0.6.

Key concepts:

Practical check, immediate feedback.

📋 Plan mode: review before executing

The agent shows what it's going to do before doing it. You approve, correct, or cancel — no scares.

What it is:

A mode where the agent writes out the steps it plans to take and waits for your approval before doing anything.

Why learn:

It's the simplest safety net in the course—you see it before it happens.

Key concepts:

Plan, approval, conditional execution.

What it is:

You ask for something → the agent writes the plan → you read, edit, or approve it → only then does it actually run.

Why learn:

Completes the visual understanding of this cycle (full diagram in module 0.5).

Key concepts:

Request → plan → review → execution.

What it is:

Large tasks that modify many files, or involve deleting/publishing things: always use plan mode. Small, reversible tasks: optional.

Why learn:

Always using it slows things down; never using it is risky — balance matters.

Key concepts:

Task risk, reversibility.

What it is:

You can ask for changes to the plan ("do it without step 3," "use a different folder name") before approving it.

Why learn:

Fixing the plan is much cheaper than undoing an execution.

Key concepts:

Feedback before the action, cost of correction.

What it is:

Vague steps ("adjust the necessary files"), or steps that mention deleting/overwriting something you didn’t ask for.

Why learn:

Knowing how to recognize this is what makes plan mode worthwhile.

Key concepts:

Specificity, plan scope.

What it is:

Ask for something small in plan mode and review the generated plan before approving it.

Why learn:

Practice is worth more than theory — seeing a real plan makes the concept stick.

Key concepts:

Repetition, familiarity with the workflow.

🔒 Permissions and security: what you should never let the agent do

The list of "never without review" items and the final exercise: create the project and have the agent introduce itself.

What it is:

Commands that delete several folders/files at once always call for plan mode and careful review.

Why learn:

It's the most costly and hardest-to-undo category of error.

Key concepts:

Irreversibility, mandatory review.

What it is:

"Production" is the live environment, used by real people — unlike the isolated test environment.

Why learn:

Covered in depth in Track 4, but the golden rule starts here: never publish without reviewing.

Key concepts:

Production, test environment.

What it is:

Make it clear in CLAUDE.md that nothing goes live (site, post, email) without your explicit approval.

Why learn:

A rule written in the file is read every time — it prevents accidental publishing.

Key concepts:

Explicit rule, human approval in the loop.

What it is:

A table showing what to authorize right away and what to always review first (full version in module 0.6).

Why learn:

Serve as a quick reference when a question comes up in the middle of a task.

Key concepts:

Gradual trust, checklist.

What it is:

Create the project, write the CLAUDE.md, and ask the agent to summarize the project itself — closing the Trilha 0 cycle.

Why learn:

It's proof that the environment is ready for Track 1.

Key concepts:

Final check, “environment ready.”

What it is:

With the terminal, project, CLAUDE.md, plan mode, and security rules ready, Track 1 introduces the WAT framework.

Why learn:

Wraps up the track with a clear next step.

Key concepts:

Track transition, environment ready.
