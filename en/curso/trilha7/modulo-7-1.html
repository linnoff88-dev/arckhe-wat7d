1

🏠 Why your assistant needs a home of its own

New here? One folder (also called a directory) is just a “drawer” on your computer where files are stored together. A folder can contain other folders—like a drawer with dividers. Throughout the course, you’ve already used separate project folders for each Build. Now it’s different: you’ll create ONE permanent folder that becomes your digital assistant’s permanent home.

Think of it this way: so far, Claude Code has been a standalone tool—you opened it in a folder, took care of something, and closed it. Starting with Track 7, it becomes a digital employee for real—and every real employee has a permanent desk, with their own drawers, where they keep what they need to work every day. Without that desk, they relearn everything from scratch with each conversation; with it, they arrive, read what’s stored there, and know where the last task left off.

💡 Main Concept

The “home” is a single, permanent folder on your computer—not a project folder that you delete later. It stores who you are, how the assistant should work, what it’s doing now, and the history of what’s already been decided.

  • •No home: every session starts from scratch, and you have to explain everything again.
  • •With a home: the assistant opens the folder, reads CLAUDE.md (topic 3), and immediately understands the context.

✓ Employee with their own desk

  • ✓Has a fixed place to store context, decisions, and supporting material
  • ✓Check the history before repeating a question you've already answered
  • ✓You know exactly where to look for what it has already done

✗ Standalone tool

  • ✗Each conversation is a different folder, with no through line
  • ✗You explain what your business is every time you need something
  • ✗Nothing gets recorded — decisions are lost between sessions
2

🗂️ The folder map: six drawers, each with one job

Inside the house, you don’t leave everything loose — you sort it into subfolders, each with a clear purpose. Six are enough to get started; none of them require anything complex, just the discipline to put each thing in the right place:

Caption: the home’s root contains a single instruction file (CLAUDE.md) and six subfolders with fixed roles — each material has its proper drawer, and the index shows where each one is.

🔍 Inside each drawer

  • context/ — who you are, what your business does, who is on the team (e.g., negocio.md, time.md).
  • rules-and-skills/ — how the assistant should behave: tone of voice, standard processes, the skills it uses.
  • projetos/ — a subfolder for each active project, with what's in progress right now.
  • decision-log/ — a dated record of what was decided and why (prevents "why did we do it this way again?").
  • references/ — supporting materials: template spreadsheets, links, PDFs, screenshots.
  • file/ — New here? "Archive" means keeping something that’s no longer active without deleting it — it may be useful later. Never delete anything moved here.
3

📇 CLAUDE.md as an index, not a repository

New here? O CLAUDE.md it’s a instruction file — a plain text file that Claude Code reads automatically whenever it opens that folder, without you having to ask. It's like leaving a permanent note at the employee's desk: "before you start, read this."

The most common mistake is treating CLAUDE.md like a storage bin: pasting everything into it—the entire history of decisions, every business detail, every rule. It grows and grows until it becomes a huge file that the assistant reads in full every time, spending time and attention on parts that aren’t relevant to the task at hand. The right approach is the opposite: CLAUDE.md stays concise e points for the right files inside the subfolders — it’s the book’s index, not the whole book. 

# CLAUDE.md — meu-assistente/

## Quem eu sou
Ver `contexto/negocio.md` (o que a empresa faz) e `contexto/time.md` (quem é quem).

## Como trabalhar
- Tom de voz e regras fixas: `regras-e-skills/tom-de-voz.md`
- Skills disponíveis: `regras-e-skills/skills.md`
- Nunca publicar nada sem eu revisar antes (regra permanente)

## O que está ativo agora
Ver `projetos/` — cada subpasta é um projeto em andamento com seu próprio status.

## Decisões importantes
Antes de sugerir mudar algo já decidido, checar `registro-de-decisões/` —
pode já ter sido discutido e descartado por um motivo.

## Nunca fazer
- Nêo colocar senha, chave de API ou dado de terceiro em nenhum arquivo desta pasta
- Nêo apagar nada de `arquivo/` sem eu pedir

A real, concise example: fewer than 20 lines, with each section pointing to the right file instead of containing all the content.

💡 Practical Tip

Practical rule: if a section of CLAUDE.md grows beyond 5-6 lines of actual content (not counting links), that’s a sign the content should become a separate file in a subfolder, with just one reference line remaining in the index.

🧭 Step by step: building the house in practice

You don’t have to create each folder by hand — it’s faster (and more reliable) to ask Claude Code itself to build the entire structure at once. The steps below show the logical order, and the copy-run block right after them does everything automatically.

Choose the location and create the root folder

A fixed location on your computer, outside temporary folders—for example, a folder called inside "Documents" meu-assistente.

2

Create the six subfolders for topic 2

context, rules-and-skills, projects, decision-log, references, archive — all empty for now, each with an already defined role.

3

Write the initial CLAUDE.md

Lean, pointing to the subfolders—even if they’re still almost empty. You’ll fill in the actual content in Phase 2 (module 7.2).

Open Claude Code inside that folder and check

Ask "what do you understand about this folder?" — if it correctly describes the structure, CLAUDE.md is being read.

⚠️ Common mistakes and what never to put in the house

Two mistakes bring the whole house down before it's even built: putting everything in one file and letting CLAUDE.md grow bloated. They share the same root cause—laziness about separating things—and both get worse over time, not better on their own.

✗ Everything in a single file

  • ✗A single “notas.txt” with business, decisions, and projects all mixed together
  • ✗Hard to find anything after a month
  • ✗The assistant has to read everything to find one small detail

✓ Organized structure

  • ✓Each type of information in the right subfolder (topic 2)
  • ✓Finding something means opening the right drawer, not reading everything
  • ✓The assistant reads only the file relevant to the task

✗ Huge CLAUDE.md

  • ✗200 lines with the entire history pasted inside
  • ✗Old, outdated information gets lost among the rest
  • ✗The assistant wastes time processing what doesn’t matter right now

✓ Concise and to the point

  • ✓Fewer than 25 lines, with a link in each section to the right file
  • ✓Easy to review everything at a glance
  • ✓The assistant goes straight to the file it needs for the task

🔒 Privacy — what NEVER goes into the home

The home is stored locally on your computer (it isn’t sent to any server on its own), but that’s no reason to be careless. Never put any of the following in any file in this folder:

  • •Passwords or API keys (for any service)
  • •Customers’ or third parties’ personal data (CPF, email, phone number without consent)
  • •Card numbers, confidential contracts, sensitive financial information

If this folder is ever shared, synced with a cloud service, or versioned in a repository (Track 7, module 7.5), anything sensitive inside it will go along too.

📈 How the home evolves — and what comes next

The home doesn’t come ready-made—it grows with use. What matters is that the structure of the six drawers can support that growth without becoming a mess, because every new thing already has the right place to go.

Day 1 — House created

Six nearly empty subfolders, with a lean CLAUDE.md pointing to them. Just the skeleton (this module).

Week 1 — Context filled in

context/ gets its first real files about the business and the team (module 7.2).

Weeks 2–3 — Projects and hands-on work

projetos/ accumulates active subfolders; regras-e-skills/ gets the skills from module 7.3.

Month 1 — First archived

Completed projects move from projetos/ to arquivo/; registro-de-decisões/ already has a useful history.

Month 3+ — Mature home

The structure stays the same — only the contents of each drawer have grown. That’s the sign that the design in module 7.1 worked.

🎯 Main Concept

  • •7.1 builds the home (here) → 7.2 fills it with life (real context) → 7.3 gives it hands (skills) → 7.4 lets it grow.
  • •The folder structure won’t change later — only the contents inside it will.
