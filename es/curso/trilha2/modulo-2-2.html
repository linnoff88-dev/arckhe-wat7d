🧬 Anatomía de un servidor MCP

Toda herramienta que tu agente obtiene mediante MCP está formada por tres piezas: lo que hace, lo que necesita saber y quién tiene permiso para usarla. Entender estas tres piezas elimina el misterio de cualquier servidor nuevo.

1

🛠️ Herramienta: el verbo que el agente puede ejecutar

¿Eres nuevo aquí? Uno protocolo es simplemente un conjunto de reglas acordadas de antemano para que dos partes puedan comunicarse sin malentenderse, como el «cambio y fuera» de la radio, pero entre programas de computadora. MCP (Model Context Protocol) es el protocolo que presentó el módulo anterior: el lenguaje común que permite que el agente converse con un servidor — un programita en ejecución (en tu computadora o en la nube de alguien) que sabe hacer algo específico y espera solicitudes. Un herramienta (en inglés, tool) es una acción concreta que ofrece ese servidor: un verbo. «Buscar el contenido de una página», «enviar un correo electrónico», «leer una fila de una hoja de cálculo». Cada servidor MCP declara su lista de herramientas junto con una breve descripción de cada una, y esa descripción es la que lee el agente para decidir cuál usar, sin que tengas que saber ningún nombre técnico.

💡 Concepto principal

Piensa en la herramienta como el nombre de un botón de un control remoto. No necesitas entender la electrónica que hay detrás — solo saber que al presionarlo ocurre eso. El servidor MCP es el televisor; las herramientas son los botones; tú solo presionas el botón correcto diciendo en portugués lo que quieres.

Leyenda: entre tu frase en portugués y la acción que realmente ocurre, hay un paso invisible: el agente decide qué herramienta del servidor MCP resuelve ese pedido.

🔍 Ver por dentro

Lo que «viaja» entre el agente y el servidor es un mensaje estructurado: no es el texto suelto que escribiste, sino un paquete con el nombre de la herramienta elegida y los valores que necesita. El servidor lee ese paquete, ejecuta la acción en el servicio real (un sitio, una base de datos, una API —la «puerta» que otro programa abre para comunicarse contigo—) y devuelve el resultado en el mismo formato. Nunca ves este intercambio en bruto; el agente traduce el resultado de vuelta a un español normal.

2

🎛️ Parámetro: lo que la herramienta necesita saber antes de actuar

¿Eres nuevo aquí? Parámetro es un dato adicional que la herramienta necesita para funcionar correctamente: la dirección del sitio, el formato del archivo de salida, el número máximo de páginas. No lo escribes a mano: el agente extrae estos valores de tu pedido en portugués y los completa por su cuenta.

✓ Ejemplo de solicitud clara

"Extrae los precios de la página ARCKHÉ AI/planos, como máximo 5 páginas." — el agente ya tiene todo lo que necesita la herramienta: URL y límite.

✗ Ejemplo de solicitud vaga

"Obtén los precios por ahí" — sin una dirección, el agente tendrá que volver a preguntar antes de poder completar los parámetros.

Todo parámetro tiene un «formato esperado»: la herramienta puede exigir un número (límite de páginas), un texto (la URL) o una opción de una lista fija (formato de salida: csv o json, por ejemplo). Cuando el parámetro es opcional, el servidor MCP suele tener un valor predeterminado: si no dices cuántas páginas, asume por su cuenta un límite razonable, generalmente pequeño, para no perder tiempo ni hacer llamadas innecesarias.

💡 Consejo práctico

Cuando no tengas claro qué necesita una herramienta, basta con pedir: «¿qué parámetros acepta esta herramienta de búsqueda?»; el agente lee la descripción técnica y te la explica en portugués, sin que tengas que abrir ninguna documentación.

3

🔑 Autenticación: la clave que demuestra quién eres

¿Eres nuevo aquí? Autenticación es la prueba de que tienes permiso para usar ese servicio; por lo general, es una «clave de API», un código secreto único que el servicio reconoce. Es como la tarjeta magnética que abre la puerta de un edificio: sin ella, nadie puede entrar, ni siquiera el agente.

💡 Consejo práctico

Guarda siempre esta clave en un archivo .env — nunca la escribas directamente en la conversación con el agente. El módulo 2.3 muestra el paso a paso completo.

La clave normalmente se obtiene al registrarte en el sitio del servicio: creas una cuenta, generas la clave en una página de configuración y la pegas en el archivo .env de tu proyecto. El servidor MCP lee este archivo por sí solo cada vez que necesita autenticarse; nunca aparece en la pantalla del chat ni se envía al agente como texto. Algunos servicios cobran por llamada o tienen un límite mensual de uso gratis: conviene comprobarlo antes de dejar que un agente se ejecute sin supervisión en un bucle.

Errores comunes en esta etapa

✗

Clave no válida o vencida: el servidor devuelve un error de autenticación y la herramienta no se ejecuta. Fix: comprueba si pegaste la clave completa en el .env, sin espacios adicionales, y si sigue activa en el panel del servicio.

✗

Límite de uso excedido: los planes gratuitos suelen tener un límite mensual de llamadas. Cuando se supera, el servicio las rechaza hasta que empiece el mes siguiente o hagas un upgrade. Fix: pídele al agente que compruebe cuántas llamadas quedan antes de ejecutar tareas en masa.

4

🧩 Las tres piezas juntas: un pedido real de principio a fin

Leyenda: las tres piezas de cualquier servidor MCP: las herramientas disponibles, los parámetros que exige cada una y la clave de autenticación que garantiza que solo tú (o quien autorices) use ese servicio en tu nombre.

Cuando pides «trae los precios de esta página», el agente: (1) elige la herramienta adecuada entre las disponibles, (2) prepara los parámetros —la URL que mencionaste, el formato de salida— y (3) el servidor MCP usa la clave de autenticación guardada para hacer la llamada real al servicio externo. Tú solo viste una frase en portugués; por debajo, las tres piezas trabajaron juntas.

Línea de tiempo de una solicitud, desde que presionas «enter» hasta la respuesta

1

Escribes la solicitud en portugués normal, sin pensar en ninguna herramienta.

2

El agente elige la herramienta correcta, leyendo las descripciones que publicó el servidor MCP.

3

El agente arma los parámetros a partir de lo que dijiste — URL, formato, límites.

4

El servidor autentica con la clave guardada en el .env y llama al servicio real.

5

El resultado vuelve — o un error, si algo salió mal — y el agente te lo traduce al portugués.

🔍 Mira por dentro: cuando el servicio responde con un error

Si falla el paso 4 —clave inválida, servicio fuera de línea, resultado vacío porque no encontró nada—, el servidor MCP no se bloquea: devuelve un mensaje de error estructurado, y el agente lo lee para decidir qué hacer después: volver a intentarlo, avisarte o sugerir otro camino. Un resultado vacío (la búsqueda no encontró nada) no es lo mismo que un error. Conviene pedirle al agente que distinga ambos casos antes de suponer que algo falló.

5

📖 Dónde ver la lista de herramientas de un servidor

Todo servidor MCP publica su documentación; por lo general, es una página en el sitio del servicio que enumera cada herramienta, los parámetros esperados y ejemplos. Vale la pena echarle un vistazo antes de instalarlo, aunque nunca vayas a escribir esos nombres a mano: ayuda a entender qué podrá hacer el agente por ti.

🔍 Por dentro

Dentro de Claude Code, ejecutar /mcp muestra los servidores MCP conectados en esa sesión y el estado de cada uno: conectado, autenticado, con error.

Cómo verificar: la lista debe mostrar cada servidor conectado con un estado — "connected", "needs auth" o algo parecido. Si un servidor que instalaste no aparece en la lista, el problema está en la instalación, no en la herramienta en sí (eso se trata en el módulo 2.3).

6

⚖️ No todas las herramientas son seguras de forma predeterminada

Algunas herramientas solo leen información (buscar, listar): bajo riesgo. Otras escriben o envían algo fuera (mandar un correo, publicar una entrada, borrar un registro): riesgo real, porque la acción ya se realizó cuando el agente termine. Claude Code te pide confirmación antes de ejecutar herramientas sensibles; no desactives esa confirmación sin pensarlo dos veces.

✓

Herramientas de lectura

Buscar, listar, leer: se pueden hacer sin mucho riesgo y, por lo general, sin pedir confirmación adicional.

✗

Herramientas de escritura

Enviar, borrar, publicar: Claude Code te pide confirmación antes de ejecutar.

Una herramienta común de lectura es el scraping — la extracción automática de información de una página de internet sin pasar por una API oficial de ese sitio. Es útil, pero exige responsabilidad: los sitios tienen términos de uso que a veces prohíben el scraping; algunos bloquean por defecto las solicitudes automatizadas (y el servidor MCP simplemente devuelve un error o una página vacía), y los datos personales de terceros que encuentres nunca deben convertirse en una hoja de cálculo o una automatización sin cuidar la privacidad. Trata el scraping como visitar una tienda física fuera del horario de atención: que la puerta no esté cerrada con llave no significa que tengas permiso para entrar cuando quieras y en cualquier cantidad.

Leyenda: las herramientas de lectura no dejan rastros irreversibles, así que se ejecutan directamente; las herramientas de escritura requieren una confirmación porque, una vez ejecutadas, muchas veces no se pueden deshacer.

💡 Consejo práctico

Si el resultado de una herramienta de lectura está vacío, no supongas que «no existe»: puede que un sitio esté bloqueando el scraping automatizado. Pídele al agente que vuelva a intentarlo o que confirme si el sitio devolvió algún error antes de concluir que la información no está ahí.
