1

🧱 Sin MCP, el agente se topa con un muro

¿Eres nuevo aquí? Hasta ahora, en la Ruta 0 y la Ruta 1, tu agente ya sabía leer y escribir archivos, ejecutar comandos en la terminal y organizar una carpeta de proyecto. Eso es mucho — pero tiene un límite estricto: solo ve lo que está dentro del computador donde se ejecuta. Pedirle que «mire tal sitio» o «lea mi hoja de cálculo de Google» sin ayuda adicional es como pedirle a alguien encerrado en una habitación sin ventanas que describa la calle de afuera.

💡 Concepto principal

  • •Archivos y carpetas locales: sí, siempre.
  • •Un sitio web, una API, una hoja de cálculo en la nube, una base de datos: no, a menos que exista un puente.

¿Eres nuevo aquí? Una API (sigla de interfaz de programación de aplicaciones) es la "puerta de entrada" que un sitio o servicio deja abierta para que los programas se comuniquen con él; sin API, la única forma de obtener datos de un sitio es abrir el navegador y copiarlos a mano. Y "protocolo" es simplemente un conjunto acordado de reglas: cómo pedir, qué informar y en qué orden. Todo protocolo existe para que dos partes desconocidas puedan entenderse sin tener que negociar desde cero cada vez; es el mismo principio que un enchufe eléctrico o un idioma común.

Leyenda: sin un puente instalado, todo lo que está fuera de la carpeta del proyecto —sitios, hojas de cálculo, bases de datos— es invisible para el agente, aunque la información exista y esté a un clic de distancia en tu navegador.

2

🔌 MCP es un enchufe estandarizado

¿Eres nuevo aquí? MCP significa Model Context Protocol — en palabras sencillas, un "acuerdo" sobre cómo un agente de IA se comunica con un servicio externo. Piensa en un tomacorriente estandarizado: cualquier aparato que siga el mismo formato de enchufe encaja en el mismo tomacorriente, sin adaptador. Antes de MCP, cada herramienta externa requería un "cable" (código) distinto para conectarse. Con MCP, todos hablan el mismo formato: el agente se conecta y ya entiende qué ofrece ese servicio.

Leyenda: a la izquierda, un agente sin MCP solo ve los archivos de la carpeta local. A la derecha, con MCP activado, se conecta a un «enchufe estandarizado» y accede a servicios externos, sin que tengas que escribir una línea de código de conexión.

Vale la pena reforzar lo que hace el MCP no es: no es una inteligencia artificial, no es un sitio web, no es una app. Es solo un conjunto acordado de mensajes, parecido al formato de un correo electrónico (asunto, destinatario, cuerpo), que tanto el agente como el servidor MCP saben crear y leer. Antes de que existiera este estándar, cada empresa que quería conectar su herramienta con un agente de IA inventaba su propio formato, y cada integración se convertía en un proyecto de programación aparte. MCP acabó con esa reinvención: un estándar publicado que cualquier servicio puede adoptar.

🔍 Por dentro

Lo que «viaja» en una llamada MCP es un paquete de texto estructurado (técnicamente JSON, pero nunca necesitas leerlo) que describe tres cosas: qué herramienta quiere usar el agente, con qué parámetros y —al volver— qué respondió el servicio. Este paquete pasa entre Claude Code y el servidor MCP que está en ejecución; si el servidor necesita comunicarse con internet (buscar una página, consultar una hoja de cálculo en la nube), entonces sí sale de tu computadora. Por eso importa la autenticación (siguiente tema).

3

🗣️ Servidor MCP: quién habla el protocolo del otro lado

¿Eres nuevo aquí? Uno servidor MCP es un programita que se ubica entre tu agente y el servicio real (Firecrawl, Google Drive, una base de datos, etc.). «Traduce» el pedido del agente al formato que ese servicio espera y traduce la respuesta de vuelta. No escribes este traductor: ya viene listo; solo lo conectas (módulo 2.3) y lo autenticas con tu propia clave.

💡 Consejo práctico

Piensa en tres roles: tú (hace la solicitud en portugués), el agente (decide qué herramienta usar) y el servidor MCP (habla el idioma del servicio externo). Nunca hablas directamente con el servicio: el servidor MCP hace de puente.

¿Eres nuevo aquí? "Autenticar" quiere decir demostrarle a un servicio que eres quien dices ser, normalmente con una clave de API, una secuencia larga de letras y números que funciona como una contraseña solo tuya, generada en el sitio del servicio. El servidor MCP guarda esa clave en un archivo llamado .env dentro de tu proyecto (crearás este archivo en el módulo 2.3): nunca dentro de la conversación con el agente, porque todo lo que pasa por el chat puede terminar guardado en algún lugar. El ejemplo de abajo es solo el formato: nunca uses una clave real en un lugar público.

Objetivo: guardar la clave en un lugar que el servidor MCP pueda leer, lejos del chat: archivo .env 
# arquivo .env na raiz do projeto
NOME_DO_SERVICO_API_KEY=SUA_CHAVE_AQUI

Cómo verificar: pídele al agente «enumera las herramientas MCP disponibles». Si responde con la lista del servicio, la clave se leyó correctamente; si aparece un error de autenticación, revisa el siguiente bloque.

⚠️ Errores comunes

  • •Clave no válida o vencida: el servidor responde con un error de autenticación. Comprueba si copiaste la clave completa, sin espacios adicionales, y si sigue activa en el panel del servicio.
  • •Clave en el lugar equivocado: si pegas la clave directamente en la conversación en vez de .env, queda visible en el historial del chat. Siempre .env, siempre local.
  • •Límite de uso excedido: muchos servicios cobran por llamada o tienen una cuota mensual gratuita. Si el agente deja de responder desde ese servidor, revisa el panel de uso antes de sospechar que hay un error.
4

🧭 El agente lee el menú y elige por su cuenta

Cuando un servidor MCP está conectado, expone una lista de «herramientas» disponibles, como el menú de un restaurante. El agente lee ese menú (el proceso técnico se llama descubrimiento de herramientas) y, según lo que pediste, elige por su cuenta cuál llamar y con qué parámetros. No necesitas saber el nombre exacto de la función ni memorizar ninguna sintaxis: solo tienes que describir lo que quieres en portugués.

✓ Tú lo haces

  • ✓Describe el objetivo en portugués: «trae los precios de esta página»
  • ✓Confirma cuando el agente te pida autorización para usar una herramienta sensible

✗ No lo necesitas

  • ✗Memorizar nombres de funciones ni parámetros técnicos
  • ✗Escribir el código de conexión con la API del servicio

En la práctica, una solicitud tuya se convierte en una breve secuencia de pasos automáticos. Mira la línea de tiempo de «trae los precios de esta página» con un servidor de scraping conectado:

1
Pides — en portugués: "trae los precios de esta página".
2
El agente consulta el menú — ve que hay una herramienta disponible para "buscar páginas".
3
El agente llama a la herramienta — envía la URL como parámetro al servidor MCP.
4
El servidor MCP busca y responde — devuelve el contenido de la página en un formato estructurado.
5
El agente organiza y entrega — extrae los precios y te los muestra en texto simple.

💡 Consejo práctico

Si el resultado está vacío o incompleto, no supongas que el agente «no sabe hacerlo». Pídele que te muestre lo que devolvió la herramienta; muchas veces el sitio bloqueó el acceso o cambió de diseño, y eso aparece en la respuesta sin procesar antes de que reformules el pedido.

5

🖥️ Local × remoto: dónde se ejecuta el servidor MCP

¿Eres nuevo aquí? Un servidor MCP puede ejecutarse de dos formas: local (un programita instalado en tu computadora, que Claude Code activa al abrirse) o remoto (una dirección en internet que ya funciona en algún servidor; solo tienes que apuntar a ella). Para el curso, usarás principalmente servidores locales instalados con un solo comando: son más fáciles de entender y auditar.

🔍 Por dentro

El servidor local funciona como un proceso común en tu computadora; incluso puedes verlo en la lista de programas en ejecución. Un servidor remoto está alojado por terceros; la comunicación pasa por internet, lo que exige más cuidado con lo que autorizas.

✓ Buen hábito

  • ✓Preferir un servidor local para los datos sensibles: se quedan en tu computadora y son más fáciles de auditar.
  • ✓Leer qué permiso solicita una herramienta MCP antes de autorizarla.

✗ Evita

  • ✗Conectar un servidor remoto desconocido sin comprobar quién lo mantiene.
  • ✗Autorizar el acceso al correo electrónico o a la base de datos «automáticamente», sin leer la solicitud.

Una nota importante, que aplica desde ahora y vuelve con fuerza en el módulo 2.5 (scraping): cuando un servidor MCP busca información en un sitio de terceros, está sujeto a los términos de uso de ese sitio y a los límites de solicitudes que impone. Algunos sitios bloquean el acceso automatizado por defecto; en ese caso, el servidor devuelve un error o una página vacía, y la solución no es «insistir más», sino comprobar si ese sitio permite ese tipo de acceso. Y si los datos incluyen información personal de terceros, trátala con el mismo cuidado que tratarías tu propia información: recopila solo lo necesario, guarda solo lo necesario.
