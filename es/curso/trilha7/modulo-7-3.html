1

🎯 Una tarea clara, no diez a la vez

¿Recuerdas al empleado nuevo del módulo 0.1? Acaba de llegar, todavía no conoce las costumbres de la casa, y tienes dos opciones: darle una tarea clara y ver cómo le va, o entregarle de una vez la lista completa de diez responsabilidades: organizar la agenda, responder correos electrónicos, encargarse de las finanzas, redactar informes, monitorear a la competencia, etc. En la vida real nadie contrata así. Con el asistente digital es igual: la fase 3 del capstone existe para que le entregues una skill, ver cómo funciona de principio a fin y solo entonces pensar en la siguiente.

La razón no es solo prudencia, también es técnica. Cada skill nueva consume espacio de contexto (el «cerebro de corto plazo» que el agente lleva consigo en una sesión) y cada MCP conectado (módulo 2.1) es una pieza más que puede fallar. Sobrecargar todo de una vez multiplica los puntos de falla y no sabes qué pieza causó el problema cuando algo sale mal. Una skill a la vez, cada una validada antes de pasar a la siguiente, es la única forma de construir un asistente confiable en lugar de un Frankenstein frágil.

💡 Concepto principal

La fase 3 no pide «dale manos completas al asistente» — pide «demuestra que una mano funciona antes de hacer crecer las otras nueve».

  • •Una skill validada genera confianza para delegar la siguiente.
  • •Diez skills sin probar generan un asistente que nadie entiende cuando falla.

2

🔍 Cómo elegir la primera skill adecuada

¿Eres nuevo aquí? Una skill, como viste en la Trilha 3, es una carpeta con instrucciones que Claude Code carga cuando las necesita: un «manual de procesos» que lee cuando la tarea requiere ese conocimiento específico. La fase 3 no pide cualquier skill: pide la primera skill adecuada, y hay una prueba de tres preguntas para encontrarla en tu propia rutina.

1

¿Se repite?

Algo que haces de nuevo cada semana (o cada día) vale mucho más la pena automatizarlo que una tarea que solo ocurre una vez.

2

¿Consume tiempo de verdad?

Si la tarea toma 30 segundos, el beneficio de automatizarla es pequeño. Busca algo que te quite minutos, o el día entero si lo olvidas.

3

¿Ya sabes explicar el paso a paso?

Si no puedes describir cómo haces la tarea, el agente tampoco podrá hacerlo. La skill debe partir de un proceso que ya existe en tu cabeza.

🔍 Por dentro

Ejemplos que suelen pasar las tres preguntas: "todos los lunes, resumir los correos no leídos de la semana", "todos los días a las 8 h, enumerar las tareas atrasadas del día anterior", "todos los viernes, generar un resumen de lo que se hizo durante la semana para revisarlo antes del fin de semana". Fíjate que ninguno exige nada fuera de lo común: es una rutina sencilla que ya existe, solo que todavía es manual.

3

📅 MCP de calendario y tareas

¿Eres nuevo aquí? MCP (Model Context Protocol) es el "estándar de conexión" que conecta el agente con servicios externos: en vez de que cada herramienta necesite un cable diferente, todos usan el mismo protocolo. Lo viste en profundidad en la Trilha 2: un servidor MCP expone funciones (p. ej., "crear evento", "listar tareas pendientes") que Claude Code puede llamar directamente, sin que tengas que copiar y pegar nada manualmente.

Para la mayoría de las primeras skills, los MCP más útiles son los de calendario (p. ej.: Google Calendar — leer y crear eventos, comprobar conflictos de horario) y de tareas (p. ej.: Google Tasks — listar tareas pendientes, marcarlas como completadas, crear nuevas). Son los que transforman una skill de «yo pienso y escribo» en una skill de «el agente revisa cómo es realmente mi día antes de actuar».

Leyenda: la programación (fase que enseñó la Trilha 6) activa la skill por sí sola; la skill consulta al MCP de calendario y al MCP de tareas al mismo tiempo; el resultado combinado te llega listo, sin que tengas que pedir nada en ese momento.

🔍 Instalar y autenticar

El paso a paso completo para instalar y autenticar un MCP — cómo registrar el servidor en Claude Code, aprobar el acceso y probar la primera llamada — está en el módulo 2.3 Instalar y autenticar. Si te saltaste la Trilha 2 o no recuerdas el proceso, vuelve allí antes de continuar: este módulo supone que ya sabes conectar un MCP.

4

🛠️ Crear la skill: prompt listo

Con la skill elegida (tópico 2) y los MCP conectados (tópico 3), el siguiente paso es pedirle a Claude Code que cree el archivo de la skill —siguiendo exactamente el framework de 6 pasos que aprendiste en la Trilha 3. El bloque de abajo es un prompt completo, listo para pegar: describe el objetivo, pide el proceso estructurado y ya le indica al agente que use los MCP adecuados.

Objetivo: crear la primera skill validada de tu asistente personal, conectada a los MCP de calendario y tareas.

Crie uma skill chamada "" na pasta de skills do
meu assistente pessoal. O objetivo dela é: .

A skill deve:
1. Usar o MCP de calendário para listar os eventos de hoje.
2. Usar o MCP de tarefas para listar pendências e as que já venceram.
3. Cruzar as duas listas e montar um resumo curto, em ordem de
   prioridade (o que tem horário marcado vem primeiro).
4. Nunca criar ou apagar nada nos serviços sozinha — só ler e
   resumir, a menos que eu peça explicitamente uma açêo.
5. Seguir o formato de skill do curso (SKILL.md com frontmatter,
   descriçêo clara do gatilho, passo a passo).

Depois de criar, rode a skill uma vez de teste e me mostre o
resultado antes de eu confirmar que está pronta.

Cómo verificar: pídele al agente que vuelva a ejecutar la skill al día siguiente, sin que tengas que recordárselo — si el resumen sale bien por sí solo, la skill está validada. Si algún dato está mal (falta un evento, hay una tarea duplicada), ajusta el SKILL.md antes de avanzar al tema 5.

💡 Consejo práctico

Cambia el fragmento entre <> según tu tarea real antes de pegarlo. El prompt funciona para cualquier combinación de calendario+tareas — lo que cambia es la descripción del objetivo.

5

⏰ Programar: para que se ejecute sola

Una skill que solo se ejecuta cuando recuerdas pedirla no es un empleado digital: es un atajo. La diferencia entre ambos es lo que enseñó Trilha 6: tareas programadas (la skill se activa sola a una hora fija, p. ej.: todos los días a las 8 h) o loops (la skill se ejecuta a intervalos y revisa algo que cambia con frecuencia). Para una rutina diaria como la del tema 4, la programación simple a una hora fija —que se estudia a fondo en el módulo 6.2— normalmente es suficiente.

El punto central: programar la skill cierra el círculo de la fase 3. Ya no abrirás la terminal por la mañana para escribir «ejecuta mi skill de rutina» — la programación lo hace por ti, y el resultado llega listo (por notificación, por archivo o por el canal que configuraste en el módulo 6.6). Es ahí donde el asistente deja de depender de tu memoria.

1

Skill validada manualmente

Lo ejecutas manualmente algunas veces, revisas el resultado y ajustas el SKILL.md si hace falta.

2

MCP conectados y probados

El calendario y las tareas responden directamente, sin errores de autenticación (módulo 2.3).

3

Programación configurada

Horario fijo definido, siguiendo el patrón del módulo 6.2: con determinismo y notificaciones incluidos (módulos 6.5 y 6.6).

4

Rutina en ejecución sin que tengas que recordarlo

La skill se activa sola durante dos o tres días seguidos, sin intervención: ese es el criterio para tener las «manos» listas.

⚠️ Atención

Programar no significa "configurar y olvidarse para siempre". Durante las primeras semanas, revisa los resultados de vez en cuando — un MCP puede perder la autenticación, un horario puede no encajar con tu rutina real. Ajustar pronto cuesta poco; descubrir 3 meses después que la skill dejó de ejecutarse, no.

6

✅ Las manos completas: errores comunes

Al cerrar la fase 3, dos pares de error/acierto resumen todo lo que pidió este módulo. El primero trata sobre el alcance: cuánto dar de una vez. El segundo, sobre la programación: si la skill realmente se ejecuta sola o sigue dependiendo de que tú lo recuerdes.

✓ Alcance correcto

  • ✓Una skill, validada de principio a fin, antes de pensar en la segunda
  • ✓MCP probados por separado, uno a la vez, antes de combinar los dos

✗ Alcance equivocado

  • ✗Pedir diez skills y diez MCPs de una vez, sin probar ninguno
  • ✗Conectar el calendario y las tareas sin confirmar que cada uno funcione por separado

✓ Programación de verdad

  • ✓Tarea programada configurada (módulo 6.2), ejecutándose sin que abras la terminal
  • ✓La notificación llega por un canal que realmente revisas

✗ Todo queda manual

  • ✗Skill lista, pero tú eres quien tiene que acordarse de ejecutarla todos los días
  • ✗Ninguna notificación configurada: el resultado queda esperando a que alguien lo abra

🎯 Concepto principal

  • •Skill validada + MCP conectados + programación real = manos completas.
  • •Con esta base sólida, comienza la fase 4 (módulo 7.4): aumentar el número de skills sin repetir el error del inicio.
