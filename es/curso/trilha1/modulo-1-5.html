1

🎯 El objetivo: investigación → redacción → envío

Llegó la hora de aplicar los cuatro módulos anteriores en un build de principio a fin: una automatización de newsletter (un correo electrónico periódico con novedades sobre un tema) que investiga un asunto, redacta un borrador y prepara el envío. Es un ejemplo lo bastante pequeño para caber en una sesión, pero lo bastante completo para practicar workflow, agente y tools juntos.

¿Eres nuevo aquí? Borrador es la versión de trabajo de un texto: no es el producto final, sino el material que alguien (tú) todavía va a revisar antes de considerarlo listo. En este build, el agente nunca entrega un correo electrónico «definitivo»: siempre entrega un borrador, porque eso es lo que indica el workflow del tema 2. La diferencia entre «el agente escribió un correo electrónico» y «el agente escribió un borrador de correo electrónico» parece pequeña, pero es lo que separa un build seguro de uno que envía algo equivocado a personas reales.

💡 Concepto principal

  • •Investigación: buscar 3-5 novedades recientes sobre un tema.
  • •Redacción: convertirlo en un texto corto, con un tono definido.
  • •Envío: preparar (o enviar) el correo electrónico final.

🔍 Por qué este build y no otro

Una newsletter combina los tres problemas que aparecen en casi toda automatización de texto: buscar información más allá de lo que el agente ya sabe (investigación), transformar información sin procesar en algo que alguien quiera leer (redacción) y realizar una acción que tiene consecuencias reales fuera de la computadora (envío). Si logras construir esto de forma segura, el mismo patrón sirve para informes semanales, resúmenes de ventas, boletines internos de equipo, cualquier cosa con el formato "reunir datos → escribir → entregar".

2

📋 Diseñando el workflow (la receta)

Antes de pedirle cualquier cosa al agente, escribe la receta, aunque sea en un borrador sencillo. Así evitas precisamente el primer error común del módulo 1.4 (receta vaga). Un buen workflow para este build: 

## Workflow: newsletter semanal sobre <seu tema aqui>
1. Buscar 3 a 5 novidades da última semana sobre o tema
2. Para cada uma, escrever 2-3 frases resumindo (tom direto, sem jargão)
3. Montar um e-mail com título + as novidades numeradas
4. Salvar como rascunho em "newsletter/rascunho-AAAA-MM-DD.md"
5. Não enviar de verdade sem eu revisar e aprovar antes

🔍 Por dentro de cada línea

  • Línea 1 (cantidad): "3 a 5" no es un número al azar: es lo bastante pequeño para que el agente investigue de verdad cada elemento (en vez de inventar para cumplir la cuota) y lo bastante grande para parecer un boletín, no una publicación aislada.
  • Línea 2 (tamaño del resumen): "2-3 frases" existe porque, sin un límite, el agente tiende a copiar párrafos enteros de la fuente, lo que además de ser largo puede convertirse en una copia directa de texto de terceros.
  • Línea 4 (dónde guardar): una ruta de archivo fija y predecible («newsletter/rascunho-...») facilita revisar siempre en el mismo lugar, en vez de buscar dónde decidió guardar el agente.
  • El paso 5 es intencional: un «freno» que impide el envío automático antes de tu revisión — práctica recomendada para la primera versión de cualquier automatización nueva.

💡 Consejo práctico

Escribe el workflow en un archivo real (p. ej.: newsletter/workflow.md) en lugar de solo pegarlo en el chat. Así permanece disponible entre sesiones y puedes indicarle al agente que lo use ("sigue el workflow.md") sin tener que volver a escribirlo todo.

3

▶️ Copy-run: el prompt listo para Claude Code

Con el workflow escrito, el siguiente paso es pegar en Claude Code una solicitud que haga referencia a esta receta. Abajo tienes un prompt completo, listo para copiar, pegar y ejecutar —ajusta solo lo que está marcado.

Objetivo: generar el primer borrador del boletín siguiendo el workflow anterior.

Crie uma pasta "newsletter/" se ainda não existir.

Siga este workflow para montar o rascunho de uma newsletter sobre
:

1. Busque de 3 a 5 novidades reais e recentes sobre o tema (últimos 7 dias)
2. Para cada uma, escreva 2-3 frases resumindo em tom direto, sem jargão
3. Monte um e-mail com título chamativo + as novidades numeradas
4. Salve como "newsletter/rascunho-.md"
5. NÃO envie nada de verdade — pare aqui e me mostre o rascunho para eu revisar

Ao terminar, me diga quais fontes você usou para cada novidade.

Cómo verificar: comprueba si se creó el archivo "newsletter/rascunho-....md", si tiene entre 3 y 5 elementos y si las fuentes citadas realmente existen (abre al menos un enlace).

🔍 Mira por dentro: lo que hace el agente en esos segundos

  • Leyendo: el agente usa una herramienta de búsqueda en la web (search) para encontrar páginas reales sobre el tema: no está «recordando» nada, sino consultando fuentes en vivo, tal como lo harías tú en una pestaña del navegador.
  • Decidiendo: elige cuáles 3-5 resultados parecen más recientes y relevantes, y decide cómo resumir cada uno en 2-3 frases sin perder el hecho principal —esa es la parte "creativa" del trabajo, y es donde más vale la pena revisar después.
  • Grabando: crea la carpeta "newsletter/" (si no existe) y guarda un archivo Markdown con la fecha en el nombre —Markdown (extensión .md) es un formato de texto simple con marcas ligeras (# para título, - para lista) que se puede abrir con cualquier editor de texto.
  • Costando: esta tarea consume algunas búsquedas en la web y un puñado de tokens de lectura y escritura; en tu plan de Claude Code, es una fracción de lo que cabe en una sesión normal. No es motivo de preocupación para un build de este tamaño.

✓ Prompt específico

Indica el tema, la cantidad, el tono, dónde guardar y que no debe enviarlo realmente. El agente no tiene que adivinar nada.

✗ "Escribe un buen boletín"

Sin tema, sin cantidad, sin destino del archivo — el agente decide todo por ti, y «bueno» no es un criterio verificable.

4

🔁 Probando y revisando el resultado

Ejecuta el prompt del tema anterior y lee con atención el borrador generado: esta es la fase de construcción del módulo 1.3, en la que vale la pena que el agente vuelva a intentarlo hasta acertar. Si el tono no encaja o alguna novedad parece inventada (puede pasar; siempre revisa las fuentes), es hora de aplicar una autocorrección guiada por ti: da comentarios específicos y pide que rehaga solo la parte que falló.

Objetivo: corregir un elemento específico del borrador sin rehacer todo.

O item 2 do rascunho está com tom formal demais e a fonte não parece
confiável. Reescreva só o item 2: tom mais direto, e busque uma fonte
diferente e mais recente. Mantenha os outros itens como estão.

Cómo verificar: vuelve a abrir el archivo y confirma que solo cambió el elemento 2, que el tono es coherente con los demás y que la nueva fuente se puede verificar.

Observa que este ciclo — ejecutar, leer, corregir un punto específico, volver a ejecutar — es exactamente la secuencia que sigue todo este build, desde cero hasta el borrador final. Puedes visualizar las etapas por las que acabas de pasar (y volverás a pasar si revisas más de una vez):

Leyenda: las etapas 3 y 4 forman un bucle — vuelves a ellas tantas veces como necesites antes de considerar que el borrador está listo. No hay un número correcto de vueltas; lo que importa es que "esté lo bastante bien para que yo lo apruebe".

5

⚠️ Errores comunes de este build

Este build específico suele tropezar con los mismos tres puntos del módulo 1.4; conviene repasarlos antes de intentarlo.

✗ Pedir sin instrucciones

"Hazme un boletín" — sin tema, sin cantidad de elementos ni lugar donde guardarlo. El agente tendrá que adivinarlo todo y probablemente se equivocará.

✗ Receta vaga

"Busca buenas novedades sobre IA" — "buenas" e "IA" (un tema enorme) sin delimitar no dan una orientación lo bastante clara.

✗ Tool sin clave

Si el paso 5 evoluciona a «enviar de verdad» (fuera de esta versión inicial), necesitarás una herramienta de correo electrónico configurada con credenciales; sin ella, el agente se detiene en ese paso. Esto se explica en profundidad en la Trilha 2 (MCP) y la Trilha 4 (Secretos). ¿Eres nuevo aquí? Credencial es la clave o contraseña que autoriza a una herramienta a actuar en tu nombre; sin ella, el agente puede saber qué hacer, pero no tiene permiso para hacerlo.

✗ Fuente inventada

El agente menciona una "novedad" sin haber buscado nada realmente, o generaliza algo que leyó en otro contexto como si fuera una noticia reciente sobre tu tema. Es el mismo riesgo de alucinación del módulo 1.3; la defensa siempre es la misma: abres el enlace y lo compruebas antes de aprobar.

6

🚀 Publicar / programar: qué sigue

Lo que construiste aquí funciona dentro de Claude Code, bajo tu supervisión: la fase de construcción del módulo 1.3. Para convertirlo en un boletín que se envíe solo cada semana, sin que abras Claude Code manualmente, faltan dos piezas que este curso cubre en las próximas rutas: darle al agente una herramienta real para enviar correos electrónicos (Ruta 2, MCP) y hacer que el workflow se ejecute en un horario fijo, publicado (Ruta 4 y Ruta 6, sobre deploy y programación).

Leyenda: el borrador manual de hoy es el primer escalón; las siguientes trilhas agregan la herramienta de envío real y la programación que te saca del camino crítico.

¿Eres nuevo aquí? Programación significa configurar la computadora (o un servidor) para que ejecute esta automatización sola, en un horario fijo, sin que nadie abra Claude Code manualmente, como un despertador para las tareas. Hasta entonces, el build de hoy ya es útil tal como está: cada vez que quieras un newsletter nuevo, abres Claude Code y ejecutas el mismo prompt del tema 3. Es trabajo manual, pero mucho más rápido que escribir desde cero.

✓ Build de hoy: tú aprietas el gatillo

Abres Claude Code, ejecutas el prompt, revisas y apruebas. No ocurre nada si no estás presente en ese momento.

→ Build futuro: el disparador es el reloj

Con Trilha 2 (herramienta de envío) y Trilhas 4/6 (deploy y programación), la misma receta se ejecuta sola cada semana —pero el freno de revisión del paso 5 puede seguir existiendo, si quieres.

💡 Consejo práctico

Guarda el workflow que escribiste en este módulo: podrás reutilizarlo casi sin cambios cuando llegue el momento de publicar, en la Ruta 4.
