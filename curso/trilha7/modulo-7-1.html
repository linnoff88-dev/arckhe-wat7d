🏠 Fase 1 — Casa: onde seu assistente digital mora

Antes de dar qualquer tarefa de verdade, seu assistente precisa de um endereço fixo: uma pasta própria, organizada, com um arquivo de instruções que ele lê sozinho toda vez que abre o trabalho. Este módulo constrói essa base — o alicerce sobre o qual as fases 2, 3 e 4 do capstone vêo empilhar.

1

🏠 Por que seu assistente precisa de uma casa própria

Novo aqui? Uma pasta (também chamada de diretório) é só uma "gaveta" dentro do seu computador onde arquivos ficam guardados juntos. Uma pasta pode ter outras pastas dentro dela — como uma gaveta com divisórias. Ao longo do curso você já usou pastas de projeto avulsas para cada Build. Agora é diferente: você vai criar UMA pasta fixa, que vira o endereço permanente do seu assistente digital.

Pense assim: até aqui, o Claude Code foi uma ferramenta solta — você abria numa pasta, resolvia uma coisa, fechava. A partir desta Trilha 7, ele vira um funcionário digital de verdade — e todo funcionário de verdade tem uma mesa fixa, com as próprias gavetas, onde guarda o que precisa para trabalhar todo dia. Sem essa mesa, ele reaprende tudo do zero a cada conversa; com ela, ele chega, lê o que está guardado ali e já sabe onde estava a última tarefa.

💡 Conceito Principal

A "casa" é uma pasta única e permanente no seu computador — nêo uma pasta de projeto que você apaga depois. Ela guarda quem você é, como o assistente deve trabalhar, o que ele está fazendo agora e o histórico do que já foi decidido.

  • •Sem casa: cada sessêo começa do zero, você reexplica tudo de novo.
  • •Com casa: o assistente abre a pasta, lê o CLAUDE.md (tópico 3) e já entende o contexto.

✓ Funcionário com mesa própria

  • ✓Tem um lugar fixo pra guardar contexto, decisões e material de apoio
  • ✓Consulta o histórico antes de repetir uma pergunta que você já respondeu
  • ✓Você sabe exatamente onde procurar o que ele já fez

✗ Ferramenta solta

  • ✗Cada conversa é uma pasta diferente, sem fio condutor
  • ✗Você reexplica quem é seu negócio toda vez que precisa de algo
  • ✗Nada fica registrado — decisões se perdem entre sessões
2

🗂️ O mapa da pasta: seis gavetas com um papel cada

Dentro da casa, você nêo joga tudo solto — separa em subpastas, cada uma com uma funçêo clara. Seis sêo suficientes para começar; nenhuma delas exige nada complexo, só disciplina de colocar cada coisa no lugar certo:

Legenda: a raiz da casa guarda um único arquivo de instruções (CLAUDE.md) e seis subpastas com papéis fixos — cada material tem uma gaveta certa, e o índice sabe onde cada uma fica.

🔍 Por dentro de cada gaveta

  • contexto/ — quem você é, o que seu negócio faz, quem é o time (ex.: negocio.md, time.md).
  • regras-e-skills/ — como o assistente deve se comportar: tom de voz, processos fixos, as skills que ele usa.
  • projetos/ — uma subpasta por projeto ativo, com o que está em andamento agora.
  • registro-de-decisões/ — um histórico datado do que foi decidido e por quê (evita "por que a gente fez assim mesmo?").
  • referências/ — materiais de apoio: planilhas modelo, links, PDFs, prints.
  • arquivo/ — Novo aqui? "Arquivar" é guardar algo que nêo está mais ativo, sem apagar — pode ser útil depois. Nunca deletar o que foi movido pra cá.
3

📇 O CLAUDE.md como índice, nêo como depósito

Novo aqui? O CLAUDE.md é um arquivo de instruções — um arquivo de texto simples que o Claude Code lê automaticamente sempre que abre aquela pasta, sem você precisar pedir. É como deixar um bilhete fixo na entrada da mesa do funcionário: "antes de começar, leia isto aqui".

O erro mais comum é tratar o CLAUDE.md como depósito: colar tudo dentro dele — o histórico inteiro de decisões, todos os detalhes do negócio, todas as regras. Ele cresce, cresce, e vira um arquivo gigante que o assistente lê inteiro toda vez, gastando tempo e atençêo em partes que nêo interessam para a tarefa do momento. O jeito certo é o oposto: o CLAUDE.md fica enxuto e aponta para os arquivos certos dentro das subpastas — ele é o índice do livro, nêo o livro inteiro. 

# CLAUDE.md — meu-assistente/

## Quem eu sou
Ver `contexto/negocio.md` (o que a empresa faz) e `contexto/time.md` (quem é quem).

## Como trabalhar
- Tom de voz e regras fixas: `regras-e-skills/tom-de-voz.md`
- Skills disponíveis: `regras-e-skills/skills.md`
- Nunca publicar nada sem eu revisar antes (regra permanente)

## O que está ativo agora
Ver `projetos/` — cada subpasta é um projeto em andamento com seu próprio status.

## Decisões importantes
Antes de sugerir mudar algo já decidido, checar `registro-de-decisões/` —
pode já ter sido discutido e descartado por um motivo.

## Nunca fazer
- Nêo colocar senha, chave de API ou dado de terceiro em nenhum arquivo desta pasta
- Nêo apagar nada de `arquivo/` sem eu pedir

Exemplo real e enxuto: menos de 20 linhas, e cada seçêo aponta para o arquivo certo em vez de conter o conteúdo inteiro.

💡 Dica Prática

Regra prática: se uma seçêo do CLAUDE.md está passando de 5-6 linhas de conteúdo real (nêo contando links), é sinal de que aquele conteúdo devia virar um arquivo separado numa subpasta, com só uma linha de referência ficando no índice.

🧭 Passo a passo: construindo a casa na prática

Você nêo precisa criar pasta por pasta na mêo — é mais rápido (e mais confiável) pedir para o próprio Claude Code montar a estrutura inteira de uma vez. Os passos abaixo mostram a ordem lógica, e o bloco copy-run logo depois faz tudo automaticamente.

1

Escolha o local e crie a pasta raiz

Um lugar fixo no seu computador, fora de pastas temporárias — ex.: dentro da pasta "Documentos", uma pasta chamada meu-assistente.

2

Crie as seis subpastas do tópico 2

contexto, regras-e-skills, projetos, registro-de-decisões, referências, arquivo — todas vazias por enquanto, cada uma com um papel já definido.

3

Escreva o CLAUDE.md inicial

Enxuto, apontando para as subpastas — mesmo que elas ainda estejam quase vazias. Você preenche o conteúdo real na Fase 2 (módulo 7.2).

4

Abra o Claude Code dentro dessa pasta e confira

Pergunte "o que você entende dessa pasta?" — se ele descrever corretamente a estrutura, o CLAUDE.md está sendo lido.

Objetivo

Pedir ao Claude Code para criar a pasta raiz, as seis subpastas e um CLAUDE.md inicial — tudo de uma vez, num único prompt.

Bloco copiável

Crie uma pasta chamada  dentro de .
Dentro dela, crie estas seis subpastas vazias:
contexto, regras-e-skills, projetos, registro-de-decisões, referências, arquivo.

Depois, crie um arquivo CLAUDE.md na raiz dessa pasta com este conteúdo:
um índice curto (menos de 25 linhas) que aponta para cada subpasta, explicando
em uma linha o que cada uma guarda (use o texto do módulo 7.1 do curso
"Seu Funcionário Digital" como referência de estilo — enxuto, sem detalhes
que deveriam estar nos arquivos de dentro das subpastas). Inclua uma seçêo

Ao final, me mostre a árvore de pastas criada.

Como verificar

Abra a pasta no seu explorador de arquivos (Finder/Explorador) e confira: uma pasta raiz, seis subpastas com os nomes certos, e um CLAUDE.md legível na raiz. Reabra o Claude Code ali e pergunte o que ele entende da pasta — a resposta deve citar a estrutura.

5

⚠️ Erros comuns e o que nunca colocar na casa

Dois erros derrubam a casa antes mesmo de ela ficar de pé: jogar tudo num arquivo só, e deixar o CLAUDE.md inchar. Os dois têm a mesma raiz — preguiça de separar — e os dois pioram com o tempo, nêo melhoram sozinhos.

✗ Tudo num arquivo só

  • ✗Um único "notas.txt" com negócio, decisões e projetos misturados
  • ✗Difícil achar qualquer coisa depois de um mês
  • ✗O assistente precisa ler tudo pra achar um detalhe pequeno

✓ Estrutura organizada

  • ✓Cada tipo de informaçêo numa subpasta certa (tópico 2)
  • ✓Achar algo é abrir a gaveta certa, nêo ler tudo
  • ✓O assistente lê só o arquivo relevante para a tarefa

✗ CLAUDE.md gigante

  • ✗200 linhas com todo o histórico colado dentro
  • ✗Informaçêo antiga e desatualizada some no meio do resto
  • ✗O assistente perde tempo processando o que nêo interessa agora

✓ Enxuto e apontando

  • ✓Menos de 25 linhas, cada seçêo com um link para o arquivo certo
  • ✓Fácil revisar tudo de uma olhada
  • ✓O assistente vai direto no arquivo que precisa para a tarefa

🔒 Privacidade — o que NUNCA vai na casa

A casa fica guardada localmente no seu computador (nêo é enviada para nenhum servidor por conta própria), mas isso nêo é motivo pra descuido. Nunca coloque em nenhum arquivo dessa pasta:

  • •Senhas ou chaves de API (de qualquer serviço)
  • •Dados pessoais de clientes ou de terceiros (CPF, e-mail, telefone sem consentimento)
  • •Números de cartêo, contratos sigilosos, informações financeiras sensíveis

Se um dia essa pasta for compartilhada, sincronizada num serviço de nuvem, ou versionada num repositório (Trilha 7, módulo 7.5), qualquer coisa sensível ali dentro vai junto.

6

📈 Como a casa evolui — e o que vem a seguir

A casa nêo nasce pronta — ela cresce junto com o uso. O que importa é que a estrutura das seis gavetas segure esse crescimento sem virar bagunça, porque cada coisa nova já tem um lugar certo pra ir.

Dia 1 — Casa criada

Seis subpastas quase vazias, CLAUDE.md enxuto apontando pra elas. Só o esqueleto (este módulo).

Semana 1 — Contexto preenchido

contexto/ ganha os primeiros arquivos reais sobre o negócio e o time (módulo 7.2).

Semana 2-3 — Projetos e mêos

projetos/ acumula subpastas ativas; regras-e-skills/ ganha as skills do módulo 7.3.

Mês 1 — Primeiras arquivadas

Projetos concluídos migram de projetos/ para arquivo/; registro-de-decisões/ já tem histórico útil.

Mês 3+ — Casa madura

A estrutura se mantém a mesma — só o conteúdo dentro de cada gaveta cresceu. Isso é o sinal de que o desenho do módulo 7.1 funcionou.

🎯 Conceito Principal

  • •7.1 constrói a casa (aqui) → 7.2 preenche a vida (contexto de verdade) → 7.3 dá as mêos (skills) → 7.4 permite crescer.
  • •A estrutura de pastas nêo muda depois — só o conteúdo dentro dela.
