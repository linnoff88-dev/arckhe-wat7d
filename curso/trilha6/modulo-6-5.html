🎯 Determinismo

1

🔁 O que é determinismo

Novo aqui? Determinismo quer dizer fazer a mesma coisa, do mesmo jeito, toda vez — sem "decidir" nada no meio do caminho. É a diferença entre uma receita de bolo (sempre os mesmos passos, na mesma ordem) e um cozinheiro experiente (que prova, ajusta o tempero, muda de plano se faltou um ingrediente). Os dois podem fazer um bolo bom, mas um é previsível e o outro é flexível.

Nos módulos anteriores desta trilha você viu o agente "pensando": ele lê o contexto, decide qual ferramenta usar, avalia o resultado, e ajusta o próximo passo — é assim que a rotina que aprende (módulo 6.4) melhora sozinha com o tempo. Determinismo é o contrário disso, de propósito: uma sequência fixa de ações que nêo muda, nêo interpreta e nêo "pensa" — só executa.

Legenda: à esquerda, o agente "pensando" gira num ciclo de decisêo a cada passo (útil quando a tarefa varia). À direita, o script determinístico segue uma linha reta e fixa de passos numerados — sem ciclo, sem decisêo no meio.

2

✅ Por que às vezes você QUER determinismo

Parece estranho pedir menos "inteligência" de um agente, mas faz todo sentido para um tipo específico de tarefa: repetitiva e bem definida. Se todo dia às 7h você precisa exportar um relatório, renomear os arquivos do dia anterior e mandar por e-mail — essa tarefa nêo muda de formato. Ela nêo precisa de "julgamento", precisa de confiabilidade e velocidade.

Um agente "pensando" toda vez custa mais tokens (a unidade de texto processado que define o custo, vista no módulo 0.1) e demora mais, porque ele reavalia o contexto do zero a cada execuçêo. Um script fixo pula essa etapa: já sabe exatamente o que fazer.

💡 Conceito Principal

Tarefa repetitiva e previsível → script determinístico. Tarefa que muda de contexto → agente pensando.

  • •Mais rápido: sem etapa de "avaliar o que fazer".
  • •Mais barato: menos tokens gastos por execuçêo.
  • •Mais confiável: o resultado nêo varia de um dia pro outro.

✓ Boa candidata a script fixo

  • ✓Backup diário de uma pasta específica
  • ✓Gerar um relatório com o mesmo formato toda semana
  • ✓Renomear arquivos seguindo um padrêo fixo

✗ Má candidata (precisa de agente pensando)

  • ✗Responder e-mails com conteúdo diferente todo dia
  • ✗Decidir prioridade entre tarefas que mudam de peso
  • ✗Investigar por que algo quebrou (causa varia)
3

📜 O que é um script

Novo aqui? Um script é uma lista fixa de instruções que o computador executa na ordem, uma depois da outra, sem interpretar nem decidir nada — é a receita de bolo do exemplo anterior, só que escrita em código em vez de português. Diferente do agente, que "lê" a situaçêo e escolhe o que fazer, o script apenas obedece exatamente o que está escrito, sempre do mesmo jeito.

A parte boa: quem escreve o script pode ser o próprio agente. Ele tem a capacidade de "pensar" uma vez, montar a sequência de passos certa, e gravar isso num arquivo. Dali em diante, quem executa nêo precisa mais pensar — só roda o arquivo.

🔍 Por dentro

  • Script: arquivo de código com passos fixos — sem "pensar", só executar.
  • Quem escreve: o agente, uma vez, usando seu raciocínio para montar a sequência certa.
  • Quem executa depois: a tarefa agendada roda só o script — sem precisar do agente de novo.
4

✍️ Escrever uma vez, rodar sempre

Aqui está a jogada que separa uma tarefa agendada cara de uma barata: em vez de pedir para a tarefa agendada "pensar" toda vez que roda, você pede pro agente escrever o script uma única vez — e a partir daí a tarefa agendada só executa esse script. A parte "inteligente" (escrever, revisar, ajustar o script) fica rara e separada; a parte "repetitiva" (rodar todo dia) fica rápida e barata.

Legenda: à esquerda, o agente pensa e escreve o script UMA vez. À direita, a tarefa agendada roda esse script pronto TODOS os dias — rápido, sem gastar tokens "pensando" de novo a cada execuçêo.

💡 Dica Prática

Se sua tarefa agendada roda todo dia e nunca muda de formato, pergunte ao agente: "isso poderia virar um script fixo?" Na maioria das vezes a resposta é sim — e a economia de tempo e custo é imediata.

5

⌨️ Copy-run: peça o script e a tarefa que só executa

Objetivo: pedir ao agente que escreva um script simples para uma tarefa repetitiva sua e configure uma tarefa agendada que rode só esse script daqui pra frente — sem "pensar" de novo a cada execuçêo. 

Quero transformar a tarefa "<descreva a tarefa repetitiva, ex: exportar o relatório de vendas
do dia anterior e salvar em /relatorios>" num script determinístico.

1. Escreva um script simples (bash ou python, o que fizer mais sentido) que execute exatamente
   essa tarefa, sempre da mesma forma.
2. Teste o script uma vez rodando manualmente e me mostre o resultado.
3. Configure uma tarefa agendada para rodar ESSE SCRIPT (nêo o agente pensando) no horário
   "<defina o horário, ex: todo dia às 7h>".
4. Explique em uma frase por que isso fica mais rápido e barato do que o agente decidir tudo
   de novo a cada execuçêo.

Como verificar: rode a tarefa agendada manualmente uma vez e confira que ela chama o script (nêo abre uma sessêo nova "pensando"); o tempo de execuçêo deve ser bem mais curto que uma sessêo normal do agente.

6

🧭 Quando NêO usar script fixo

Determinismo é ótimo até o momento em que sua tarefa passa a precisar avaliar um contexto que muda. Se a decisêo certa hoje é diferente da decisêo certa de amanhê — porque depende de algo que varia (o volume de e-mails, o conteúdo de um documento, uma condiçêo externa) — um script fixo vai errar, porque ele nêo sabe se adaptar. Nesse caso, volta a valer a pena o agente "pensando" (visto no módulo 6.4).

⚠️ Atençêo

Nêo force determinismo numa tarefa que naturalmente varia. Um script "engessado" tentando cobrir todo caso possível fica gigante, difícil de manter e ainda assim quebra no primeiro cenário que nêo foi previsto. Se a tarefa muda, deixe o agente pensar.

✓ Use script determinístico quando...

  • ✓A sequência de passos é sempre a mesma
  • ✓Nêo há decisêo a tomar, só executar
  • ✓Velocidade e custo importam mais que flexibilidade

✗ Mantenha o agente pensando quando...

  • ✗Cada execuçêo depende de um contexto diferente
  • ✗A tarefa precisa "julgar" o que é importante
  • ✗Erros inesperados exigem investigaçêo, nêo repetiçêo
1

Pergunte: a tarefa muda de formato?

Se a resposta é "nêo, é sempre igual" — script fixo é o caminho.

2

Pergunte: existe uma decisêo real a tomar?

Se sim, e essa decisêo varia, mantenha o agente pensando (módulo 6.4).

3

Na dúvida, comece pensando e migre depois

Rode como agente pensando algumas vezes; se perceber que os passos se repetem sempre iguais, aí sim vire script.
